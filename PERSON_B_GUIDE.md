## 3. Step-by-Step Execution Plan for Person B

### Step 1: Mock the Shared Contract & Build Ingestion Hub
1. Take the Canonical Security Baseline Schema agreed upon with Person A and save a mock JSON file (`mock_audit_result.json`).
2. Build the **Unified Ingestion Hub**:
   * Drag-and-drop file upload zone (accepts `.cfg`, `.conf`, `.txt`, `.json`, `.zip`).
   * Direct CLI text paste area for rapid testing.
   * Vendor selector dropdown with an "Auto-Detect Vendor" option.
   * Framework selection checkboxes: **CIS Benchmark**, **DISA STIG**, **NIST SP 800-53**, **ISO/IEC 27001**.
   * One-click "Audit Configuration" button that submits the payload to the backend.

### Step 2: Implement the AI Dynamic Adaptation Engine (The Core Innovation)
1. **Initialize the Local Embedding Model**:
   * Load the lightweight `all-MiniLM-L6-v2` embedding model using `sentence-transformers` / `onnxruntime`.
   * Pre-compute vector embeddings for standard canonical security attributes:
     * `management_access.telnet_disabled` -> "disable telnet, no telnet, block telnet service"
     * `management_access.ssh_version` -> "ssh version 2, enforce ssh protocol v2, crypto key rsa"
     * `aaa.session_timeout` -> "exec timeout, idle timeout, session timeout limit, auto logout"
     * `logging.syslog_servers` -> "remote syslog host, logging server, audit log destination"
     * `aaa.password_encryption` -> "service password-encryption, secret sha256, password hash"
2. **Semantic Similarity & NER Pipeline**:
   * When Person A's parser passes an unmapped line:
     * Use `sentence-transformers` to compute the vector embedding of the raw line.
     * Calculate cosine similarity against all pre-computed security attributes.
     * Use `spaCy` to extract numerical parameters (e.g. `10` minutes) or entity values (e.g. cipher names).
     * Find the highest-scoring candidate and assign a **Confidence Score (0.0 to 1.0)**.
3. **The Active Learning Confidence Gate (via `modAL`)**:
   * If Confidence $\ge 0.95$: Automatically map the line and tag as `[AI Auto-Mapped]`.
   * If Confidence $< 0.95$: **Trigger the Low-Code Training Loop**; flag the line as `MANUAL_REVIEW_REQUIRED` and route it to the training queue.

### Step 3: Build the Interactive Low-Code Training Studio
Build the dedicated GUI tab where the administrator interacts with the AI (inspired by `Doccano` / `Label Studio`):
1. **Unrecognized Commands Table**:
   * Shows: Line number, raw command text, detected vendor, AI candidate category, and AI confidence score (e.g. `87.4%`).
2. **Low-Code Mapping Controls**:
   * **Accept Button**: Single click to accept the AI suggestion.
   * **Reassign Dropdown**: Allows admin to pick a different security category if the AI made a mistake.
   * **Parameter Extractor**: Automatically highlights extracted values with an editable field.
3. **The Zero-Downtime Crystallization Engine**:
   * When the admin clicks "Confirm Mapping", generate a regex rule (e.g. `r'idle-timeout\s+(\d+)'`).
   * Store this rule in an **Active Heuristic Cache** (in-memory + persisted JSON/SQLite file).
   * **Instant Hot-Reload**: Re-evaluate the configuration immediately without restarting the backend server or redeploying any container. The UI shows the compliance score update in real-time!

### Step 4: Build the Audit Results, Diff Viewer & Remediation Exporter
1. **Executive Scorecards**:
   * Radial gauge or circular progress bar showing the Overall Compliance Score (0–100%).
   * Framework cards showing individual percentages for CIS, DISA STIG, NIST 800-53, and ISO 27001.
2. **Filterable Findings Table**:
   * Search bar + filter pills: `All`, `Failed (Critical/High)`, `Passed`, `Manual Review`.
   * Expanding rows showing: Control title, framework reference, found configuration snippet, expected standard, and remediation explanation.
3. **Side-by-Side Configuration Diff Viewer (`Diff2Html` / `Monaco`)**:
   * Visual red/green diff highlighting lines that need to be removed vs. new hardening lines that must be added.
4. **Remediation Exporter**:
   * One-click "Copy CLI Remediation Script".
   * One-click "Download `.cfg` / `.sh` Script".
   * One-click "Export Ansible Playbook" (`remediation.yml`).
   * One-click "Download Official NTRO PDF Report".

### Step 5: Containerization & Kubernetes Manifests
1. **Multi-Stage Distroless Containerfile**:
   * Stage 1: Build the backend and assets in a Go/Python builder container.
   * Stage 2: Copy only the final executable, models, and policy files into `gcr.io/distroless/static-debian12:nonroot`.
   * Set `USER nonroot:nonroot` and expose port `8080`.
2. **Kubernetes Manifests**:
   * `deployment.yaml`: Deployment spec with resource requests/limits and `readOnlyRootFilesystem: true`.
   * `hpa.yaml`: Horizontal Pod Autoscaler scaling workers from 2 to 10 pods when CPU > 70%.
   * `cronjob.yaml`: Nightly automated drift detection job pulling configs and alerting on non-compliance.
   * `networkpolicy.yaml`: Air-gapped egress lockdown (allowing internal management subnet SSH only; denying all public internet).

### Step 6: Multi-Vendor Sample Dataset & Deliverables
1. **Curate Sample Configurations** (at least 8 vendors from the Batfish dataset and vendor samples):
   * `cisco_ios_xe_sample.cfg` (Misconfigured Telnet, HTTP enabled, no logging)
   * `juniper_junos_sample.conf` (Weak SSH, missing idle timeout)
   * `palo_alto_panos_sample.xml` (Permitted IP misconfigured, weak ciphers)
   * `fortinet_fortios_sample.conf` (Admin Telnet enabled, short password length)
   * `arista_eos_sample.cfg` (SNMPv1 community string present)
   * `sonic_whitebox_sample.json` (Custom white-box switch config for testing the AI training loop)
2. **Prepare Hackathon Deliverables**:
   * **2-Page Architecture Document** (`ARCHITECTURE.md`): System diagram, data flow, normalization schema, and AI learning loop.
   * **5-Slide Technical Pitch Deck** (`PRESENTATION.md`): Problem & operational gap, our solution, AI dynamic adaptation innovation, enterprise & defense impact, and live roadmap.
   * **2-Minute Demo Video Script**: Walkthrough showing: 1) Uploading misconfigured Cisco config, 2) Viewing STIG/CIS failures, 3) Ingesting unseen SONiC config, 4) Using the Low-Code Training GUI to map the command in real-time, 5) Downloading the certified PDF report.
